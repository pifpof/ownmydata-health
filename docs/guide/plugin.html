Plugin guide · v0.2

Hand it over. Claude files it.

The ownmydata plugin is a set of skills for Claude. You drop in a lab report, a visit note or a photo of a letter, or just say what happened, and Claude writes it into your vault: linked to the right problem, with the original kept untouched. You never fill in a form.

What you need

  • Claude, with access to a folder on your computer: Claude Code, or the Claude desktop app with a Project linked to a folder.
  • A folder for your vault on your own computer (how to choose one).
  • Your documents, whenever you have them: PDFs, photos of paper, pasted text. You can also start with nothing and just talk.

Everything the plugin writes is plain text. You don't need to know anything about FHIR, markdown or file formats to use it; they're there so your records stay portable.

Install the plugin

From GitHub (recommended)

In Claude Code, run:

/plugin marketplace add pifpof/ownmydata-health
/plugin install ownmydata@ownmydata

From the zip file

  1. Download ownmydata.zip from the latest release and unzip it. You get a folder called ownmydata.
  2. In Claude Code, from the folder that contains ownmydata, run: 
    /plugin marketplace add ./ownmydata
/plugin install ownmydata@ownmydata

To try it for one session without installing: claude --plugin-dir ownmydata.zip.

Single skills (Claude desktop)

Each release also has one .skill file per skill. In the Claude desktop app, go to Customize → Skills and upload them one at a time. Start with setup-health-vault.skill: it carries the empty vault template the others rely on.

Commands are namespaced. Once installed, every command starts with /ownmydata:, for example /ownmydata:capture. You rarely need to type them: plain words like "add this" or "catch me up" work too.

Choose a folder

Pick or create an empty folder on your own computer, for example Documents/Health vault. Avoid:

  • Cloud-synced folders (iCloud, Dropbox, Google Drive, OneDrive), unless you're comfortable with your health records being copied there too. Setup warns you, in one line, if the folder you pick looks like one.
  • Folders inside another Claude vault or a git repository, so your health records don't mix with other notes or end up in version control.

You can move the folder later; it's just a folder. See moving your vault.

Set up a Claude Project

A dedicated Project in the Claude desktop app keeps health sessions separate from everything else. It's optional in Claude Code (just work inside the vault folder), and strongly recommended in the desktop app.

  1. Create a new Project and link it to your vault folder.
  2. If the Project has a memory setting, turn it off, or make sure that memory isn't shared with your other chats. The vault is the memory.
  3. Paste this into the Project instructions:
This project is my personal health vault. The linked folder is the vault, and the ownmydata plugin maintains it.

1. At the start of every conversation, read CLAUDE.md in the vault folder and follow it exactly. It holds the safety, privacy and filing rules. If the folder has no memory.md yet, run /ownmydata:setup-health-vault first.
2. Use only the ownmydata skills here (/ownmydata:capture, intake, start, save, health-check, recenter). Never use another plugin's capture, sync, save, minutes or query skills in this project, even if a request sounds like one of theirs. Anything health-related goes into this vault and nowhere else.
3. When I drop in a document or tell you something that happened, capture it. Don't ask me to fill in details.
4. Never write my health information to Claude's memory, to any other folder or project, or into a web search.
5. If I describe sudden or severe symptoms, tell me to get urgent care first, before anything else.
Point 2 matters if you use other plugins. A notes or "chief of staff" plugin may also have a capture or save command. Without that line, "add this" with a lab report could be picked up by the wrong plugin and filed outside your vault.

Create your vault

In the Project (or in Claude Code, inside your vault folder), run:

/ownmydata:setup-health-vault

Claude asks two things, one at a time:

ClaudeWhat name should the vault use for you? Just how you'd like it shown.

YouPat Sample

ClaudeWhere should the vault live? I'll use this folder unless you name another.

YouHere is fine.

It copies the empty vault into the folder, explains in one paragraph where your data stays, and ends by inviting your first document. That's all. It never asks about your conditions or medicines up front: the vault learns from what you hand it.

If the folder already has a vault, setup stops and changes nothing.

The three habits

01 · anytime

Hand it over

Drop in a document or say what happened. "Add this" works; so does /ownmydata:capture.

02 · opening

Start

/ownmydata:start or "catch me up": a few lines on each problem being followed, its last event, and what you're waiting on.

03 · closing

Save

/ownmydata:save or "that's all for now": anything not yet filed gets filed, and the summary for next time is refreshed.

And once, when you have 15 minutes: say "take my health history" for the interview. Every so often, say "check my vault" for a health check.

Handing things over

Anything about your health can go in. Claude decides what kind of record it is, writes it, and links it to the problem it belongs to.

Documents

  • Attach or drop a file into the conversation: lab results, a visit summary, a consultation or referral letter, an imaging or hearing-test report, a discharge summary, a prescription label, a vaccine record.
  • A photo of paper works. Anything Claude can't read clearly is marked as unclear, never guessed.
  • Pasted text works too; it's kept as a text original.
  • Several at once: drop them all, or put them in the vault's data/inbox/ folder and say "file what's in the inbox". You get one combined summary at the end.

The original is copied into data/documents/<year>/ and never edited again. Each original's fingerprint goes into data/load-log.md, so the same document is never filed twice: hand it over again and Claude just tells you where it already is.

Sentences

You don't need paperwork. Say what happened, in your own words:

YouSaw the ENT today, she ordered a hearing test.

ClaudeSaved: ENT visit (2026-10-12), linked to Left ear investigation.

YouStarted vitamin D, 1000 units a day.

ClaudeSaved: Vitamin D 1000 units daily, as something you take now.

Things you say are recorded as your account ("from what you told me"), never dressed up as a doctor's diagnosis. Vague dates stay in your words: "as a teenager" is kept as "as a teenager", not turned into a year.

What you get back

Every capture ends with one line per main record, each starting with Saved:, and nothing else to do. Claude never asks you to fill in a missing field: if the document doesn't say it, the record doesn't either.

Checking and correcting

When a document has numbers in it, Claude lists the ones it read, so you can glance at them against the original:

Saved: Blood tests (2026-11-05), 3 results, not linked to any problem.

Please check these numbers against the original so you know I read them correctly:
- Ferritin 1?2 ug/L (middle digit unclear on the photo)
- Hemoglobin 147 g/L
- TSH 2.1 (no unit printed)
  • Something's wrong? Say so: "the ferritin is 182". Only that value changes, and Claude replies with the corrected line ("Fixed: Ferritin 182 ug/L.").
  • All correct? Say "numbers look right" and those records are marked as checked against the original.
  • No time? Don't reply. Nothing happens, nothing nags you. Unchecked records simply say so wherever they're shown.

Your health history

Documents rarely cover the background a new doctor asks about: allergies, past operations, family history. The interview fills that in. Start it with /ownmydata:intake or "take my health history". It takes about 10 to 20 minutes and only ever runs when you ask.

Claude asks the questions a family doctor asks a new patient, one at a time, in this order:

  1. About you
  2. Allergies
  3. Medications
  4. Ongoing conditions
  5. Past illnesses and hospital stays
  6. Operations and procedures
  7. Injuries
  8. Family history
  9. Vaccines
  10. Check-ups and screenings
  11. Lifestyle (substance use only if you say yes)
  12. Mental health (only if you say yes)
  13. Reproductive and sexual health (only if you say yes)
  14. Care team
  15. Devices
  16. Anything else

Each section opens with a yes-or-no question, so a "no" moves straight on. Follow-ups are short and few. If your records already show something, Claude mentions it and only asks if there's more.

You're in control

SayWhat happens
"skip"Next question, no comment.
"I don't know"A complete answer. Nothing is recorded for that detail.
"next section"Moves on to the next topic.
"pause"Stops. Everything so far is saved. Say "continue my health history" any time to pick up where you left off.
"actually, I forgot…"Adds or corrects it, then returns to where you were.

The private sections

Mental health, substance use, and reproductive and sexual health are only asked about after you say yes. A "no" is final for that interview. Anything you share there is stored as private: it's left out of the end-of-interview read-back, and the viewer hides it until you choose to show it.

At the end, Claude reads back what it saved, one line per section, so you can catch mistakes.

Problems over time

Health rarely happens in one visit. When something needs following (a symptom being investigated, a condition being treated), Claude opens an episode: one page for "the ear thing", with a summary, the open items you're waiting on, and a timeline of every visit, result and medicine linked to it.

  • Refer to it however you like: "my ear", "the hearing thing". Episodes remember the names you use.
  • New documents about it are linked to it automatically.
  • When it's over, say so: "the ear thing is sorted, it was wax". At the next save, Claude closes the episode with a short written conclusion: what happened, what was done, and anything the records still show as open.

Claude only closes a problem when you say it's over, never by guessing.

Asking questions

Ask in plain words. Claude answers from your records and names the source.

YouWhat happened with my ear?

ClaudeThe ENT saw you on 2026-10-12 and recorded "left-sided hearing loss, likely conductive" (consultation note, 2026-10-12). You had a hearing test on 2026-11-18, and the same day you said it was wax, cleared at the clinic.

Useful questions: "What medicines am I on?", "When was my last blood test, and was anything flagged?", "What did I want to ask the doctor?", "Who's my ENT?". If a value hasn't been checked against its original, the answer says so.

Claude tells you what your records say, not what to do. It won't interpret a result as good or bad beyond the flags the lab printed, and it won't suggest starting or stopping treatment. Bring the questions to your clinician; the vault makes sure you have the facts.

Inside your vault

Your vault is a folder of plain markdown files you can open in any editor. You never need to touch them, but it helps to know what's there.

your-vault/
├── CLAUDE.md          how Claude behaves here: safety, privacy, tone
├── memory.md          the map: which folder holds what
├── memory/
│   ├── _state.md      what's open right now
│   ├── episodes/      one page per problem being followed
│   ├── conditions/  encounters/  reports/  medications/
│   ├── allergies/  immunizations/  procedures/  family-history/
│   ├── patient/       you, plus care-team/ and devices/
│   ├── library/       questions for doctors, notes you asked to keep
│   └── reference/     the rules Claude follows when it writes
├── data/
│   ├── inbox/         drop files here to be filed
│   ├── documents/     your originals, never edited
│   └── load-log.md    a fingerprint of every original
└── outputs/  trash/
  • One record per file. Each opens with a block of structured data (in HL7 FHIR R4, the standard health systems use) followed by a short readable summary and its links.
  • Every folder has an index and a change log, so you (or any AI) can see what's there and what changed when.
  • Originals are sacred. Nothing in data/documents/ is ever edited.

To browse it comfortably, use the viewer app. To see a complete example, look at the fictional sample vault.

Keeping it healthy

Health check

Every month or so, say "check my vault" (/ownmydata:health-check). Claude checks every record against the vault's rules, rebuilds the indexes, timelines and summary card, fixes what is safe to fix (broken links, missing log lines, outdated rule files) and reports the rest in plain words. It never changes a value, unit, range, flag or clinical wording.

Recenter

In a long session, Claude can drift: asking too many questions, sounding like it's giving advice, mentioning "missing fields". Say "you're asking too many questions" or /ownmydata:recenter, and it re-reads the vault's rules and corrects course.

Backups

Your vault is a folder, so back it up like any important folder: an external drive, or an encrypted backup you control. If you ever put it under git, the vault's .gitignore already keeps your records out of commits; never push a real vault to a public repository.

Privacy and safety

  • Your vault is a folder on your computer. The project's code and examples never contain anyone's real data.
  • The AI provider processes what you share. When you give Claude a document, its contents are processed so it can be read, as with anything you share with Claude.
  • Claude writes your health information only into the vault: never into its own account memory, never into a web search.
  • Keep health sessions separate. Use a Project with its memory off or separate, or an incognito chat, so the conversation itself isn't remembered elsewhere.
  • Private topics stay private. Mental health, reproductive and sexual health, substance use and genetic results are marked private and handled with extra care.
Not medical advice, and not an emergency service. If you describe sudden or severe symptoms, or anything that suggests you might harm yourself, Claude stops filing and tells you to get help first. Please do: contact your doctor, an urgent care service or your local emergency number.

Command reference

Plain words work for all of these; the commands are there if you prefer them.

CommandOr sayWhat it does
/ownmydata:setup-health-vault"set up my health vault"Creates an empty vault. Two questions: your name and the folder.
/ownmydata:capture"add this", or just describe what happenedFiles a document or a sentence, links it, lists numbers to check. Also takes corrections and "numbers look right".
/ownmydata:intake"take my health history"The one-question-at-a-time background interview. Pause and resume any time.
/ownmydata:start"catch me up", "what's open"A short brief: problems being followed, last events, what's pending.
/ownmydata:save"that's all for now", "wrap up"Files anything left, closes finished problems, refreshes the summary card.
/ownmydata:health-check"check my vault"Checks every record, rebuilds indexes and timelines, fixes safe things.
/ownmydata:recenter"you're asking too many questions"Re-reads the vault's rules when a long session drifts.

Troubleshooting

My document was filed by a different plugin

Another plugin with a similar command picked it up. Add the Project instruction (point 2 matters), or use /ownmydata:capture explicitly. Then hand the document over again.

Claude says it can't find the vault template

The install is incomplete. Reinstall the plugin. If you installed single skills in the desktop app, make sure setup-health-vault.skill is the one from the release.

"That one's already in your vault"

That exact file was filed before; Claude links you to the record. Nothing is duplicated.

A number was read wrong

Say the right value ("the creatinine is 87, not 78"). Only that value changes. Photos with glare or smudges are the usual cause; a clearer photo or the PDF helps.

Claude keeps asking me to fill things in

It shouldn't. Say /ownmydata:recenter or "stop making me fill things in". It re-reads its rules and stops.

My vault was set up with an older version

Nothing to do. The first time you run the interview or a health check, Claude refreshes the vault's rule files from the plugin. Only the plugin's own rule files change, never your records.

Moving your vault

Move or copy the whole folder, then re-link your Claude Project to the new location (and choose it again in the viewer). Nothing inside depends on where the folder sits.
